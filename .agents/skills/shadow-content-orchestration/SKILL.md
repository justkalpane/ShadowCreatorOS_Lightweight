# Shadow Content Orchestration

Use this skill for any request involving:

- script
- YouTube
- Shorts
- video
- content
- reel
- voiceover
- context engineering
- topic
- storytelling
- debate
- critique

## Required Behavior

Before answering, run repo-first Shadow orchestration:

1. Read `AGENTS.md`.
2. Read `START_HERE_FOR_AGENTS.md`.
3. Read `AGENT_READ_ORDER.md`.
4. Use WF-200 script route for script/content tasks.
5. Select directors, agents, subagents, skills, and subskills with evidence paths.
6. Run research gate and capability gate.
7. Produce final content plus the content engineering packet.
8. For every 3-10 minute YouTube script, consume
   `runtime_contracts/SCRIPT_STORY_ENGINE_CONTRACT.md` and include a 45-75
   second `CINEMATIC_SHORT_STORY_BLOCK` after the hook and before the main
   teaching section.
9. When a real person, real incident, brand, company, factual case study, or
   biographical proof is used, run web-assisted research when web access is
   available and cite the source evidence.
10. Default the first master script to English unless the user explicitly asks
    for another language or translation/localization.
11. Use dynamic beat durations. Do not emit a rigid 15-second grid without a
    production reason.
12. When a final Media Factory draft is requested, include a scene sync matrix
    and local/cloud/hybrid execution plan.
13. Treat the three hook variants as opening-hook candidates only. For every
    3-10 minute YouTube script, place topic-relevant recurring re-hooks at a
    dynamic 70-90 second default interval, never leave an unexplained gap above
    90 seconds, and include at least three internal re-hooks plus a CTA hook for
    a 5-minute script.

Do not produce generic LLM content before repo routing.

## Required Output

For script/video/content tasks, include:

- Shadow Mission Packet
- Registry-first route
- Director/agent/subagent/skill/subskill evidence
- Research brief
- Script V1
- Debate
- Critique
- Final script
- Content engineering packet
- Quality gate
- Lineage summary
- Cinematic short story block for every 3-10 minute YouTube script
- Claim evidence status for real-world proof claims
- Script language declaration and user-language request check
- Source ledger and fact-versus-anecdote map for real-world proof
- Dynamic timed beat map
- Scene sync matrix for Media Factory final drafts
- Recurring re-hook map bound to final script, dynamic beat map, editing
  context, and line-by-line influence map

## Forbidden Behavior

- Do not answer directly with generic script output before repo routing.
- Do not skip `AGENTS.md`.
- Do not skip capability routing or registry evidence.
- Do not create files unless explicitly approved.
- Do not mark a real-person or real-incident proof story `PASS` without source
  references.
- Do not infer Hindi, Hinglish, or another output language from culture,
  celebrity, location, or mythology.
- Do not treat source presence as source sufficiency.
- Do not treat three opening-hook variants as full-script retention coverage.

## Proof Implications

- `PASS`: full repo-first route, registry evidence, content engineering, gates, and lineage are present.
- `PARTIAL`: useful content but missing agent/capability/source/context engineering evidence.
- `FAIL`: generic direct answer, invented registry items, false execution claims, or skipped repo startup.
